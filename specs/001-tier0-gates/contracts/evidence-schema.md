# Interface Contract: Evidence Schema

**Feature**: `001-tier0-gates` | **Version**: 1.0 (2026-10-20)

Two machine-readable formats exist: one JSON record per gate, and JSON Lines for the probe. Both are
validated before they are written, and re-validated by `npm run validate` before any commit.

## 1. Gate record — `evidence/gates/<id-lowercase>.json`

```json
{
  "schemaVersion": 1,
  "gateId": "G01",
  "runState": "done",
  "verdict": "PASS",
  "reason": null,
  "startedAt": "2026-10-20T09:14:02Z",
  "finishedAt": "2026-10-20T09:21:47Z",
  "endpoint": "https://test-evm-rpc-v3.portaldot.dev",
  "chainIdObserved": "420420777",
  "commands": [
    {
      "command": "node src/gates/g01.ts --rpc $PORTALDOT_EVM_RPC_URL",
      "cwd": "apps/gates",
      "exitCode": 0,
      "rawOutput": "evidence/raw/g01/01-deploy.txt",
      "ranAt": "2026-10-20T09:15:10Z"
    }
  ],
  "measurements": [
    {
      "name": "deploy-gas",
      "value": 412345,
      "unit": "gas",
      "method": "receipt",
      "conditions": { "compiler": "solc-0.8.28", "evmVersion": "paris" },
      "txRef": "0x…"
    }
  ],
  "transactions": [
    {
      "hash": "0x…",
      "kind": "deploy",
      "from": "0x…",
      "to": null,
      "blockNumber": 123456,
      "status": "success",
      "explorerUrl": null,
      "receiptPath": "evidence/raw/g01/deploy-receipt.json"
    }
  ],
  "errors": [],
  "verdictReason": "Contract deployed and a read call returned the stored value.",
  "classification": null,
  "adaptation": null,
  "evidenceFiles": ["evidence/raw/g01/01-deploy.txt"]
}
```

### Validation rules

| Rule | Enforcement |
| --- | --- |
| `gateId` matches an existing gate | reject unknown ids |
| `runState` ∈ {done, blocked, not_run} and is always present | reject missing or other values |
| `done` ⇒ `verdict` ∈ {PASS, PARTIAL, FAIL} | reject missing or other values |
| `blocked` or `not_run` ⇒ non-empty `reason` and `verdict` is null | reject |
| PASS ⇒ every `requiredMeasurements` entry present | reject with the missing names listed |
| PASS ⇒ `classification` and `adaptation` are null | reject |
| `done` non-PASS ⇒ `classification` present; `FAIL` is never used for an unavailable environment | reject |
| `DESIGN-CHANGE` or `FALLBACK-TRIGGER` ⇒ non-empty `adaptation` or matched condition | reject |
| `FALLBACK-TRIGGER` ⇒ `verdictReason` names one of the five conditions | reject |
| `not_run` ⇒ `reason` names the halted gate | reject |
| every `evidenceFiles` path exists and is under `evidence/` | reject |
| every `commands[].command` passes `sanitize()` | reject, exit 3 |
| timestamps parse as ISO-8601 UTC and `finishedAt >= startedAt` | reject |
| a transaction in `transactions` with `status: success` has a `receiptPath` | reject |

JSON is written with sorted keys, two-space indentation and a trailing newline so diffs are stable.

## 2. Probe log — `evidence/rpc-log/<YYYY-MM-DD>.jsonl`

One object per line, no trailing comma, no array wrapper:

```json
{"at":"2026-10-20T09:00:03Z","evm":{"ok":true,"latencyMs":142,"chainId":"420420777","blockNumber":88123,"error":null},"ws":{"ok":true,"latencyMs":61,"bestBlock":88123,"error":null}}
```

Rules:
- Append-only. A line is never edited or deleted, including on a later run.
- Exactly one of `ok: true` or a non-empty `error` per side.
- `at` is UTC with second precision; duplicate `at` values within one second are allowed only when a
  retry occurred, and the retry carries `"retry": true`.
- A sealed day file (UTC date in the past) is never opened for append.
- Gaps are detected by `npm run rollup`, which reports missing intervals as gaps. It never
  synthesises entries.

## 3. Rollup — `evidence/tier0-results.md`

Generated by `npm run rollup` from the records, then reviewed by hand only for prose, never for
numbers. If hand-editing would change a number, the underlying record is wrong and is fixed instead.

Rollup never refuses because a record is missing. A missing record is rendered as
`NOT RUN — halted at <gate>` when the sequence stopped, or `BLOCKED — <reason>` when the gate exists
but could not run. It refuses only on malformed records, where "malformed" means a record that fails
the schema rules above, not an absent one.

Required structure:

```markdown
# Tier 0 Chain Gates — Results

Generated: <UTC> | Window: <first> → <last> | Probe coverage: <pct>%

## Gate table
| Gate | Question | Run state | Verdict | Classification | Evidence |
| --- | --- | --- | --- | --- |

## What this makes possible
## What this makes impossible
## What changes in the design
## Starting facts
| Fact | Claimed | Observed | Status | Evidence |
## Open questions
```

Rules:
- One row per gate, always ten rows. `done` rows show the verdict; `blocked` and `not_run` rows show
  the state and the reason instead of a verdict.
- Every `Evidence` cell links to the record and at least one raw artifact.
- "What this makes impossible" is mandatory even when empty, and says "nothing" explicitly rather
  than being deleted.
- The starting-facts table carries all eight supplied facts with `confirmed` / `corrected` /
  `unconfirmed`.

## 4. Secret patterns rejected in every artifact

- any value of a loaded environment variable from the key list;
- `PRIVATE_KEY=`, `--private-key`, `--mnemonic`, `--seed` in a recorded command;
- a 64-hex string that is not declared as a hash in the same record;
- `BEGIN … PRIVATE KEY`.

A hit aborts the write, exits 3, and prints only the field path that matched — never the value.
