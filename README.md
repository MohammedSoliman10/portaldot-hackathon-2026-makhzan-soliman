# Makhzan

Bonded, challenge-verified storage on Portaldot, with an accountable AI agent as its first customer.

## Repository

https://github.com/MohammedSoliman10/portaldot-hackathon-2026-makhzan-soliman

## Status

Tier 0 in progress: a measurement harness verifies the Portaldot chain assumptions before any
Makhzan product code exists. No product contract, provider daemon, UI or agent has been written.

## Known limits

- Identical blocks, and whole identical subtrees, are interchangeable in a Merkle proof by design: one stored copy answers either challenge and this does not reduce what a provider must store (FR-017, DR-011).

## AI assistance

This project is built with AI assistance. AI-assisted parts are marked in commits with `[ai]` and disclosed here as they appear:

- Repo skeleton, `.gitignore`, `.env.example`, `AGENTS.md`: AI-written.
- Spec Kit scaffolding (`.specify/`, `.opencode/commands/speckit.*`): generated by GitHub Spec Kit (AI-assisted workflow tooling).
- Tier-0 gate harness (`apps/gates/`): AI-written TypeScript, reviewed by the owner at each checkpoint.
- Probe contracts under `contracts/src/tier0/`: AI-written, disposable, deleted or quarantined before the product tier.

### Compiler paths

The primary path is standard Foundry/`solc` (EVM bytecode), because the chain reports
`allowEVMBytecode=true`. The fallback path compiles the same Solidity source with the official
`resolc` 1.4.0 CLI into a PolkaVM blob. Standard Foundry 1.8.5 has no `--resolc` flag; the
ParityTech `foundry-polkadot` fork is the only supported `forge build --resolc` path and is not
installed here. Both paths share `apps/gates/src/lib/deploy.ts`; the resolc binary is installed
outside the repository at `~/.local/bin/resolc` and is not committed.
