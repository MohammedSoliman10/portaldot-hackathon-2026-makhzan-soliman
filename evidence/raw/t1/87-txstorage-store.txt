== answer ==
YES — the owner account could store a ~300-byte payload. [measured] data size and fee; [design note] authorization rule.
1. 300 bytes is inside 1..8,388,608 (MaxTransactionSize). [measured]
2. paymentInfo for transactionStorage.store(300 B) from the owner returns a fee and does not error. [measured]
3. Authorizations has 0 entries, while 19 stored transactions exist on chain: storing does not require an entry for a signed origin. [measured]
4. The pallet's store path charges byte_fee*size + entry_fee = 4,000 planck and does not consult Authorizations; the authorization scope exists for the unsigned/preimage path. [design note, read from the pallet source]
caveat: this is a dry-run answer. No store transaction was signed or sent, so the dispatch path was not exercised end-to-end.
caveat: the pallet source read is polkadot-sdk master; the deployed runtime is spec 3002 and exposes the same calls, storage items and errors, but the runtime code itself was not audited line by line.
