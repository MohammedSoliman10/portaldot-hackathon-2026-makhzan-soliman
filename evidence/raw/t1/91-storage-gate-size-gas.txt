target: StorageGate runtime under 1,500 B (spec FR-007, 'if possible').
measured: 2,055 B runtime, 2,209 B initcode -> 555 B over the target.

where the bytes go (each variant built with the same foundry flags, then reverted):
  3 entry points, no guard calls, no events                                 1,201 B
  + the inlined guard (healthOf + dealOf at every call site)                2,055 B
    => the guard costs 854 B, about 285 B per inlined copy.
  no events, one NotHealthy() error instead of the four named guard errors  1,861 B
    => even the stripped floor is over 1,500 B.

why it is left at 2,055 B: the only way below 1,500 B is to stop inlining the guard
(a linked external library, which adds a second deployment and a trust address) or to
collapse the three entry points. Neither is worth it for a showcase whose point is the
named refusal and a reusable internal library. Reported, not hidden.
